# 架构说明

DiveTrail · 尾迹是 Windows 本地桌面应用。它通过 Win32 检查前台游戏窗口，用 MSS 截图，以 RapidOCR、ONNX Runtime 和 OpenCV 识别屏幕信息。Python 负责数据写入和统计，pywebview 通过 Edge WebView2 显示界面。运行数据在本机 SQLite 和数据目录内保存。

```text
前台 Apex → 区域截图 → 场次与待识别队列 → OCR / 英雄识别
                                         ↓
补图分组预览 → 用户确认 → 场次关联 → SQLite 战绩与证据
                                         ↓
                             统计与 RP 复核 → Api.state → UI
```

| 边界 | 职责 |
|---|---|
| `app.py`、`windows_capture.py` | 管理窗口和采集线程，响应 F8、可选的 Windows 登录启动及游戏窗口检查。 |
| `capture_journal.py`、`screen_scout.py` | 持久化采集任务并识别页面类型；同一场次的 HUD、总结和经验值分别处理。 |
| `recognition.py`、`heroes.py` | 从截图提取证据；无法确认的字段保留为空。用户确认的英雄样本可用于后续匹配。 |
| `import_images.py`、`storage.py` | 组织手动补图并维护记录归属，保存对局、场次和截图引用。 |
| `migrations/`、`store_backup.py` | 升级本地结构并处理便携备份；导入前校验内容和文件引用。 |
| `rp_progress.py`、`rp_reconcile.py`、`player_stats.py` | 计算排位校准、可解释的 RP 估算，以及自己与固定队友的英雄统计。 |
| `ui/` | 使用 pywebview 接口读取和修改本地数据，负责筛选、图表和交互。 |

公开包用画面区域的文字确认页面类型。未附带游戏图像模板时，英雄头像及部分局内战斗数字可能无法确认。

## 行为约定

- **场次与证据**。记录、截图和采集任务分别保存。同一画面重复出现时按场次和证据去重；有不同场次标识的截图分开归组。
- **来源与缺失值**。局内快照可以补足未采集到的结算，保留独立状态。统计只使用存在的数据，并区分 OCR 实读、校准和估算。
- **本地档案**。游戏昵称经过归一化后用于关联所属记录。历史记录优先从旧场次的档案信息确认归属。归属不明的记录保留在数据库，避免混进其他档案统计。
- **依赖方向**。采集、识别和 RP 计算可以离开实际游戏回放。窗口和系统操作留在桌面边界，便于自动测试。

调整数据结构时先验证旧版本数据库、便携备份和部分失败的恢复路径。新增统计应复用已有记录和字段来源。
